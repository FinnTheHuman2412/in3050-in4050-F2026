# Teaching guide

## The 2 x 45-minute rhythm

| Time | Activity | Goal |
|---|---|---|
| 0-5 min | Welcome and retrieval | Establish the question for the session |
| 5-15 min | Menti diagnostic | Expose background knowledge and misconceptions |
| 15-30 min | Build the mental model | Explain the smallest useful idea |
| 30-43 min | Guided notebook | Make the idea visible |
| 43-45 min | Checkpoint | One vote or prediction before the break |
| 45-55 min | Break | Reset attention |
| 55-70 min | Student experiment | Change one parameter and observe the result |
| 70-82 min | Failure case and transfer | Diagnose where the method stops working |
| 82-88 min | Exam-style question | Recognize the idea in unfamiliar wording |
| 88-90 min | Exit ticket | Reveal what needs repetition |

The exact timing can move, but preserve student experimentation and the exit ticket.

## Weekly preparation checklist

- Identify three concepts students must be able to explain.
- Choose one misconception worth exposing.
- Build one plot whose output changes visibly.
- Include a prediction before revealing the output.
- Add one basic task and one optional IN4050 extension.
- Test all notebook cells from top to bottom.
- Prepare one optional section to skip.
- Keep normal preparation close to two hours.

## Notebook conventions

- **Predict** before revealing an output.
- **Explain** for pair discussion or a written response.
- **Experiment** when students modify code or parameters.
- **IN4050 extension** for deeper mathematics or implementation.
- End with define, apply and diagnose questions.

## Menti conventions

Menti is an interaction layer, not a second lecture deck.

- Ask short questions that reveal reasoning.
- Show the response distribution before explaining.
- Ask students to defend competing answers.
- Run a notebook experiment when a misconception can be made visible.
- Revisit the idea later with different wording.

## Publishing workflow

1. Develop in a private TA workspace when solutions are involved.
2. Remove solutions and private notes.
3. Restart the kernel and run every cell.
4. Check all relative links and data paths.
5. Commit with a descriptive message.
6. Publish solutions only when course policy explicitly permits it.
